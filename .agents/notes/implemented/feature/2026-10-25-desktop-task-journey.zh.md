# Agent Note: 桌面任务过程

Status: implemented

[English](2026-10-25-desktop-task-journey.md) | 中文

## Problem

桌面轨迹将用户请求、系统提示、运行上下文、工具参数和计时指标混在一起。密集的记录表让普通用户难以理解任务进展。

## Decision

桌面书桌模式默认使用基于既有轨迹投影的纵向「任务过程」。它展示用户请求、助手回复和工具行动；有记录的工具描述作为行动标题。搜索保留完整命中轮次。全文原位展开，「查看记录详情」选中原记录表中的对应记录。显式的工具定位请求直接打开「技术记录」。

时间线显示最近六个已加载轮次，并提供更早历史入口。它展示已记录行动数与实际运行、失败状态；工具结果缺失时保留未知状态。它不推断计划或虚构完成百分比。系统与上下文行仍可在「技术记录」查看。其他客户端保留原有默认视图。

## Alternatives considered

只修改记录表样式仍然需要用户理解密集信息。替换检查器会损失诊断能力。模型生成摘要会增加等待，也可能歪曲实际行动，因此过程视图使用已有描述和内容。

## Consequences

用户获得可读的任务过程，无需第二套事件存储或会话格式。原有时间概览、搜索和检查器仍然可用。没有记录易读描述时，仍可能显示技术工具名。行动数只覆盖已加载历史，过程视图不承诺任务整体完成状态。

## Verification

过程组件测试覆盖请求、行动、结果、失败、运行中调用、缺失结果、搜索和检查器跳转。构建后的桌面场景检查过程与记录切换，以及 390、600、1680 像素下的横向溢出。
